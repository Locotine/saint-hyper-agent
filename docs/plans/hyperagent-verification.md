## 4. Known gaps to report

- Protected-path detection needs a git baseline: in a non-git project folder, or a repo without a first commit, gates still run but test edits are not flagged (P3).
- The automatic 70 % trigger only applies to flow steps; plain threads fork on request (tool or action) (P6).
- Flow steps now run in a Saint-managed worktree (`worktreesDir/flow-<id>`, branch `saint/flow-<id>`); a project that is not a git repository (or has no commit) still runs in the project folder, and a kill there does not freeze it (P8).
- Writes to protected zones are enforced as read-only mounts of the files that exist when a sandboxed process starts, plus the gate's edit check; a new file created in a protected zone is caught only by the gate (P8).
- Inside bwrap, writes to HOME outside the provider's state dirs land in a throwaway tmpfs (P8).
- Tripwires watch flow steps always and every thread only from L3; an agent that legitimately names a credential path in a flow step is stopped too (P8).
- Quota failover switches provider, not account: rotating between accounts of the same provider is not implemented (P7).
- Quota is detected from the session's last error text; a provider that reports quota differently is treated as an ordinary turn failure (P7).

- Edge `workspace: fresh` (a node in its own worktree) is not implemented: all steps of a flow share the flow's worktree (P2/P8).
- Node threads use `creationSource: "flow_node"`; check the sidebar and Kanban show or hide them as intended (P10–P12).

- Windows has no OS sandbox: L2+ autonomy and auto-approve stay locked there.
- macOS sandbox tests cannot run on the Linux dev machine; they run on macOS CI or a Mac.
- Provider resume after hibernation must be confirmed per provider; providers that cannot resume are excluded.
- Hibernation is recorded only for stops Saint made; the existing 30-minute reaper still stops sessions without marking them (P9).
- "Wake" clears the hibernated mark and the session restarts on the agent's next message. It does not start the provider at once: `ProviderCommandReactor` deliberately never starts a session without a turn, because a session in `starting` with no turn makes the composer and work log look active (P9).
- Per-thread RSS/CPU covers Claude, Codex, Antigravity and the ACP providers (Cursor, Devin, Droid, Grok, Omp). OpenCode runs one shared server for every thread and Pi runs in-process, so their processes show without a thread (P9).
- MCP Hub runs each opted-in stdio server once and serves it to agents as the connector `<name>_hub`. The user's own per-provider copy keeps running until they remove it from that provider's config, so memory is only saved after that. Shared servers run with the home folder as cwd, so servers that depend on the project folder should not be shared. Server-to-client requests (roots, sampling) are refused and server notifications are dropped (P9).
- Admission: flow steps queue on pressure and wait on critical memory or full seats; `saint_create_threads` from an agent is refused (`host_busy`) on critical memory or full seats. Threads a person starts are never blocked (P9).
- Windows per-process rows come from one `Get-CimInstance Win32_Process` call per minute; untested on Windows (P9).
