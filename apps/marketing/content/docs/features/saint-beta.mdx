<Callout type="warn" title="Saint Beta is retired">
  From Stable 1.0.11, every feature ships in Saint and Stable no longer offers to install or copy
  data into Beta. An installed Beta keeps its status card with the way back to Saint. To move Beta
  data into Saint once, quit both apps and run `copy-saint-beta-data.sh` (macOS and Linux) or
  `copy-saint-beta-data.ps1` (Windows) from the [latest release
  assets](https://gitlab.com/locotine/saint-releases/-/releases). The Saint data it replaces is kept
  as a backup. The rest of this page describes Stable 1.0.10 and earlier.
</Callout>

Saint Beta is a separate desktop app for trying upcoming features. It installs beside Stable Saint, uses its own data folder and update feed, and receives prerelease updates. A Stable release does not turn your Stable app into Beta.

## Join from Stable

On macOS, open **Settings → General → Saint Beta**. Choose **Install Saint Beta** to download and open the latest available Beta release, or **Copy my data and open** to install it if needed and then bring a snapshot of your Stable data into Beta. The download is checked before installation. If no Beta prerelease has been published yet, try again after it becomes available.

On Windows and Linux, the settings card opens the public download page. For Beta, open the [1.0.9-beta.1 release assets](https://gitlab.com/locotine/saint-releases/-/releases/v1.0.9-beta.1) and select the Beta installer for your platform. The website’s current download snapshot follows Stable.

## Keep your work separate

Stable uses `~/.saint`; Beta uses `~/.saint-beta`. Copying Stable data into Beta replaces existing Beta chats, projects, and settings after confirmation. Work made only in Beta can be lost in that copy, while Stable data stays as it was. Quit Beta before requesting another import. If Beta is older than the Stable data format, update Beta and retry.

Use **Open Beta** in Stable settings to reopen an installed Beta without copying data. In Beta, **Switch back to Saint** opens Stable. Changes made only in Beta are not copied back.

## Diagnostics and feature availability

Beta sends crash reports and anonymous usage statistics only when its operator configured a diagnostics endpoint; this fork ships none. Its settings explain what is shared. Stable does not send Beta diagnostics. Avoid putting credentials or private material into bug reports you submit yourself.

Supported provider accounts, models, and permissions depend on their installed runtimes. [Oh My Pi](/docs/providers/omp) is available in both Stable 1.0.0 and Beta.

## Updates

The two apps follow separate update feeds. A Beta update cannot replace Stable, and a Stable update cannot replace Beta. If an update does not appear, check the [public releases](https://gitlab.com/locotine/saint-releases/-/releases) for the newest Beta prerelease and compare its version with the version shown in your app.

Source evidence: Saint release head `BETA.md`, `packages/shared/src/betaFeatures.ts`, `apps/desktop/src/betaChannel.ts`, and the Beta settings controls in `apps/web/src/components/settings/DesktopSettingsPanels.tsx`.

## Shared feature availability

[Connectors](/docs/features/connectors) and [native editor intelligence and JavaScript debugging](/docs/features/workspace-editor#native-editor-and-javascript-debugger) are enabled for Stable 1.0.9 and later, and [Remote hosts](https://gitlab.com/locotine/saint-hyper-agent/-/blob/main/REMOTE.md#3-remote-ssh-hosts) for Stable 1.0.10 and later, with the same functionality already available in Beta. Existing installed Stable builds need an update; this promotion does not import Beta credentials or data.

[Hubs and Library](/docs/features/hubs) are available in Stable 1.0.2 and later; [inline visuals](/docs/features/inline-visuals) are available in Stable 1.0.5 and Beta. Tasks, Inbox, Auto-fix CI, Oh My Pi, the rail workspace and message trail sound are also available in both apps. Beta keeps its independent update feed, data home and diagnostics policy. Stable never sends Beta diagnostics.
