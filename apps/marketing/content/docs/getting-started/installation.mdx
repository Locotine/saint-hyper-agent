Saint is a desktop workspace for coding agents. Installing Saint gives you the workspace; provider runtimes and model access still come from the coding-agent tools and accounts you already use.

## Choose the right installer

Download the latest stable build from the [Saint download page](/install). If the automatic download is unavailable, open [GitLab Releases](https://gitlab.com/locotine/saint-releases/-/releases) and select the asset for your system.

| Platform               | Download                                           |
| ---------------------- | -------------------------------------------------- |
| macOS on Apple Silicon | Arm64 `.dmg`                                       |
| macOS on Intel         | Not published for 1.0.12; check the release assets |
| Windows                | x64 `.exe` installer                               |
| Linux                  | x86_64 `.AppImage`                                 |

<Callout type="info" title="Saint does not include a model subscription">
  Saint uses provider runtimes installed on your machine. Install and authenticate at least one
  provider—such as Claude Code, Codex, OpenCode, Cursor, or another supported runtime—before
  starting your first task.
</Callout>

## Install Saint

<Steps>
<Step>

### Download the application

Use the [download page](/install) or an official GitLab release. Avoid third-party download mirrors.

</Step>
<Step>

### Complete the platform installation

Open the downloaded installer and complete the normal installation flow for your operating system.

On macOS, a release built without an Apple Developer ID is not notarized, so the first launch shows **“Saint” Not Opened** (“Apple could not verify…”). Choose **Done**, then open **System Settings → Privacy & Security**, scroll to **Security**, choose **Open Anyway** next to the Saint message, and confirm with your password or Touch ID. macOS remembers the choice for that copy of the app. On macOS 13 and 14 you can instead Control-click Saint in Applications and choose **Open**.

If macOS says Saint **is damaged and can’t be opened**, the copy predates ad-hoc sealed builds and has no **Open Anyway** button. Install a newer release, or remove the download quarantine once: `xattr -dr com.apple.quarantine /Applications/Saint.app`.

On Linux, your desktop environment may require making the AppImage executable before opening it:

```bash
chmod +x Saint*.AppImage
```

To add Saint to the application menu and let the in-app updater replace the AppImage, run `install-saint.sh` from the same release: `bash install-saint.sh` installs the newest `Saint-*.AppImage` in `~/Downloads` as `~/Applications/saint.AppImage`; `bash install-saint.sh --uninstall` removes it and keeps your data in `~/.saint`.

</Step>
<Step>

### Install and authenticate a provider

Follow the provider's official installation and sign-in process. Saint does not copy an account from another machine or replace the provider's own authentication.

Open a fresh terminal and confirm that the provider can start successfully outside Saint. This separates provider installation problems from Saint configuration problems.

</Step>
<Step>

### Launch Saint and check the provider

Open Saint, go to provider settings, and confirm that the runtime is detected and available. Saint discovers the models and options exposed by the installed runtime, so the choices can vary by provider version, account, and subscription.

</Step>
<Step>

### Add a project

Choose a local project folder. A Git repository is strongly recommended because it enables branches, worktrees, diffs, commits, pushes, and pull-request workflows.

</Step>
</Steps>

## When a provider is not detected

Work through these checks in order:

1. Open a new terminal window.
2. Confirm that the provider executable runs there.
3. Confirm that the provider is authenticated.
4. Check whether Saint offers a custom binary-path setting for that provider.
5. Restart Saint after changing your `PATH` or installing a new runtime.
6. Continue with [Troubleshooting](/docs/troubleshooting) if it remains unavailable.

Saint normalizes the environment available to the desktop process, but provider installations and shell configurations differ across operating systems.

## Updating Saint

Packaged builds use Saint's desktop updater. When an update cannot be applied automatically, download the newest installer and install it over the existing application.

The application bundle and local workspace data are stored separately. Even so, keep important work committed to Git before updating an early release.

## Run without the desktop shell

Each GitLab release also includes `saint-server-<version>.tar.gz` for a headless web installation. It requires a supported Node.js runtime and a production dependency install; it is not a standalone executable or a replacement for provider authentication.

Follow the [Headless server guide](/docs/workflows/headless-server) for extraction, startup, readiness checks, data-directory ownership, and remote-access policy. Start loopback-only and do not expose the raw server port without deliberate authentication and trusted transport.

<Callout type="warn" title="Saint is under active development">
  Saint changes quickly. Keep valuable work committed and review release notes before relying on a
  new workflow for important repositories.
</Callout>

## macOS minimum in 1.0.9

Saint requires **macOS 13 or later** for its bundled native tools. Stable 1.0.9 packages declare that minimum and updater feeds refuse the update on older macOS systems. Choose the installer matching your processor. Packaged startup checks on macOS 15 do not establish runtime behavior on every macOS 13 configuration.
